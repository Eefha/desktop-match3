这份文档讲的是“为什么这么做”，不是功能清单。做法是：先用一句约束把问题缩小， 再用取舍把方案减到最薄，然后把纯逻辑锁在中间层，最后用自动化手段去测那些“肉眼看不见”的地方。

一、从一句约束开始，而不是从玩法开始
“屏幕上不能出现任何‘游戏’的东西。” 大多数项目从“我要做个消消乐”出发，会一路走向开始界面、关卡、皮肤、音效。这个项目反过来。

约束一旦立住，后面九成的选择都自动有答案了：要不要加音效、要不要震屏、要不要排行榜弹窗， 拿它一比就能定，不必争论审美。三条硬原则直接落地：画面无游戏感（没有标题栏 / 开始界面 / 按钮 / 说明）； 背景必须是真桌面（裁真实壁纸、用系统原图、套系统真实间距）；随时能走（ESC 立刻消失，退出时分数照样入榜）。

二、七个关键取舍（每个都留着“放弃过什么”）
当时的决策放弃的方案理由
覆盖式重画桌面真挪桌面图标
（LVM_SETITEMPOSITION）		 视觉只差一点，但程序崩了会毁掉用户桌面 —— 摸鱼工具不该担这个风险
只占左侧 58%整屏覆盖 + 复刻任务栏 真任务栏就在旁边，复刻不如借用；删掉一半代码，真实度反而更高
用用户自己的桌面图标现成美术素材 零美术成本且每人棋盘独一无二；代价是要用算法保证十种棋子一定分得清
直接发 140 字节整盘只发 seed 各自生成 换掉“两边随机序列不一致”这类极难复现的 bug，140 字节对 TCP 和蓝牙都是零压力
先到先得claim 占位 + 350ms 租约锁 房主是唯一权威、天然串行；省掉锁表与“抢输了”的回滚抖动，手感反而更干脆
传结算后整盘 + 消掉的位置传 clear / fall / spawn 事件流 事件流要重放随机补充，两边一旦分叉棋盘就歪了；整盘只有 140 字节
手写 Win32 原生窗口tkinter 打包解释器没带 Tk；两套 GUI 争消息泵会和 SDL 无边框窗口打架
三、分层：让“纯逻辑”待在中间
main.py └─ app.py 渲染与主循环：布局、缓动、连锁、计分、结算、联机接入 ├─ engine.py 纯逻辑：三消判定、重力、死局、洗牌、同步结算 ├─ winicons.py 平台适配：256px 图标、壁纸填充、图标间距、DPI ├─ netcore.py 传输：帧协议 / TCP / UDP 广播 / 蓝牙 RFCOMM ├─ netplay.py 联机状态机：房间、两种玩法、实时比分 └─ settings_win.py 窗口外壳：Win32 + 离屏渲染 + 系统 EDIT 控件

依赖方向单向：engine.py 不知道 pygame 存在，也不知道网络存在。判断分层对不对的标准只有一句： 中间层能不能被另一个完全不同的前端直接用。

可测

不开窗口就能跑 60 步一致性与死局检测

可当权威

可移植

小程序版能复用同一套公式与随机数，因为逻辑层是干净的

四、怎么验证“看不见的东西”

这个项目的界面是“假装成桌面”，很多问题肉眼看不出来：125% 缩放下格子错位、壁纸接缝对不上、 看着消了但数据没消。所以验证手段本身也是设计的一部分。

手段解决什么
main.py --selftest无窗口跑布局、图标、计分、联机全链路，结果写日志；打包进 exe
tools/smoke.py60 步连续游走，逐步比对显示层与数据层是否始终一致
tools/net_smoke.py两个 Game 走真实 TCP，A / B 两种玩法各跑一遍
tools/probe_exe_*.py用真实 Windows 鼠标消息点打包后的 exe，而不是只测源码
tools/shot_*.py离屏渲染出图，代替“我自己开一下看看”
tools/shot_readme.py把 USERPROFILE 指到临时假桌面 + 合成壁纸，截图不泄露真实文件名
五、九轮迭代：每轮都能独立交付
1 – 2
能跑 & 像桌面：图标→棋子打通三消闭环；壁纸裁切、真实间距、256px 图标、选中框、文件名字体
3 – 4
手感 & 收尾：缓动、碎屑、连锁倍率、死局检测与重排；结算卡片、历史前十、ESC 记分退出
5
专门做减法：整屏 → 左半屏，砍掉复刻任务栏与假文档窗口
6
打包：PyInstaller 单文件，自检塞进 exe
7 – 8
联机：先写评估（三种形态 / 三种权威模型），再实装 TCP + UDP 发现 + 蓝牙，A/B 两模式
9
交互重构：玩法与联机搬进独立原生子窗口，首次运行自动弹窗引导

两个刻意选择：先做视觉真实度，再做联机（“像不像桌面”决定这东西能不能用，联机是锦上添花）； 第 5 轮专门做减法，不是等到收尾才删代码。

六、踩过的坑，和它们教的东西
坑教训
打包后打开还是旧界面PyInstaller 的 build/ 缓存不因改源码失效，每次必须 --clean 并删 build；用自检日志核对版本
设置窗口一片白StretchDIBits 第 12 参是 iUsage，要传 DIB_RGB_COLORS = 0；SetBkColor 在 gdi32 不在 user32
关掉窗口后键盘失灵窗口期间 SDL 事件队列会堆积，只认 QUIT、其余丢弃
用户找不到设置入口功能做对了不等于能找到：首次自动弹窗 + 底栏常驻按钮 + Ctrl+J 三条路
历史最高分被覆盖写存档要用“只升不降”的累加式更新，别整份覆盖

共同的一条：这类“窗口 + 图标 + 打包”的项目，难的不是算法，是和操作系统打交道的那一层。 所以每个平台调用都单独收进 winicons.py / settings_win.py，出问题能一眼定位到哪一层。

七、如果重来，会改哪里

① 一开始就该只占半屏 —— 整屏覆盖 + 复刻任务栏浪费了大约两轮，最后全被删掉。 ② 窗口层应该更早抽象 —— 若第一轮就走通“离屏渲染 → 贴到 Win32 窗口”，后面很多 UI 能更早搬出棋盘。 ③ 联机应先做“同种子竞速”再评估共享棋盘，别一上来把仲裁和同步一起做。 ④ 还要补：蓝牙双机实测、多显示器、改用 onedir 解决首启 2~3 秒与杀软误报。

只给 30 秒时，我会这么讲

① 它把桌面图标变成棋盘，所以零美术成本、零学习成本，看起来就是桌面； ② 真正的难点全在和操作系统打交道——提取 256px 原图、裁壁纸对齐接缝、DPI、原生子窗口，不在三消算法； ③ 联机不依赖服务器，房主即服务器，两个人连上就能抢同一块盘。
